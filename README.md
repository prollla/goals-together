# Цели вместе

VK Mini App для отслеживания личных целей и привычек с поддержкой друзей.

## Реализовано

- Три модели целей: отказ от привычки, регулярное действие и количественный результат.
- Каталог шаблонов, конструктор цели и редактирование (всё, кроме типа).
- Расписания: каждый день, по будням (выходные не влияют), N раз в неделю (серия в неделях).
- Отметки за сегодня и вчера, пропуски (серия прерывается после 3 пропусков подряд), сброс результата.
- Серия, календарь, общий прогресс, бессрочные и завершённые цели.
- Все цели (личные и общие) хранятся в Node.js API и SQLite — одинаковые на всех устройствах;
  цели из старого `localStorage` один раз переносятся на сервер вместе с историей.
- Общие цели: приглашение по ссылке, прогресс участников, кнопка «Поддержать».
- С сервисным ключом VK: проверенные имена и аватары, вечерние напоминания и уведомления о поддержке.
- Ежедневные резервные копии базы.
- Мобильная вёрстка с нижним меню и desktop-вёрстка с боковой панелью; светлая и тёмная темы.

## Локальный запуск

Требуется Node.js 20.19+ или 22.12+.

```sh
npm install
npm run server
```

Во втором терминале:

```sh
npm start
```

API работает на `http://127.0.0.1:3001`, база создаётся в `server/data/goals.db`. На текущем компьютере также можно использовать `start-server.cmd` и `start.cmd`: они находят установленный Node.js или локальный runtime из `.runtime`.

Для проверки другого локального пользователя добавьте `?dev_user=2` перед hash в адресе приложения. Этот режим предназначен только для разработки.

## Проверка

```sh
npm run lint
npm run build
npm test
```

`npm test` запускает три набора: логику серий и прогресса (`tests/goals-logic.test.ts`), API в production-режиме
с проверкой подписи VK (`tests/api.test.cjs`) и «Поддержать»/уведомления/резервные копии против поддельного VK API
(`tests/social.test.cjs`). Тесты API требуют Node.js 22 (как в Docker-образе). На GitHub всё это запускается
автоматически для каждого pull request (`.github/workflows/ci.yml`).

## Публикация API

Для реальной синхронизации через VK нужен отдельный HTTPS-сервер с Node.js и постоянным диском для SQLite.

Переменные окружения сервера:

- `NODE_ENV=production` — обязательная проверка подписи launch-параметров VK.
- `VK_APP_SECRET` — защищённый ключ приложения; хранить только на сервере.
- `PORT` — порт API, по умолчанию `3001`.
- `DATABASE_PATH` — путь к файлу SQLite на постоянном диске.
- `VK_SERVICE_KEY` — необязательно, «Сервисный ключ доступа» приложения (VK → управление приложением → Ключи доступа).
  Включает проверенные имена и аватары (берутся из VK API, а не от клиента), вечерние напоминания в 20:00
  по времени пользователя и уведомления «… поддерживает вас». Без ключа всё работает, но этих функций нет,
  а переключатель напоминаний в приложении скрыт.
- `BACKUP_DIR`, `BACKUP_KEEP` — каталог для ежедневных резервных копий и сколько последних хранить (по умолчанию 14).

В production API не принимает идентификатор пользователя из обычных заголовков: он проверяет HMAC-подпись VK launch-параметров с помощью `VK_APP_SECRET`.

Уведомления приходят только тем, кто включил напоминания в приложении и разрешил уведомления в системном окне VK.

## Docker

Контейнер работает от пользователя `node`, использует read-only файловую систему и слушает только `127.0.0.1:3001` на сервере. SQLite сохраняется в именованном volume `goals-api-db`.

```sh
cp deploy/goals-api.env.example .env
```

Укажите настоящий `VK_APP_SECRET` (и при желании `VK_SERVICE_KEY`) в `.env`. Каталог для резервных копий
должен принадлежать пользователю контейнера (uid 1000):

```sh
mkdir -p backups && chown 1000:1000 backups
docker compose up --build -d
docker compose ps
curl http://127.0.0.1:3001/api/health
```

### Резервные копии

Сервер делает копию базы при запуске и затем раз в сутки в `./backups` (рядом с `docker-compose.yml`), хранит
последние 14. Копии лежат на том же диске, поэтому периодически забирайте их на другой компьютер:

```sh
scp root@94.228.170.88:/путь/к/проекту/backups/goals-*.db .
```

Восстановление из копии:

```sh
docker compose stop
docker run --rm -v goals-api-db:/data -v "$PWD/backups":/backups alpine \
  sh -c "cp /backups/goals-ГГГГ-ММ-ДД-ЧЧ-ММ-СС.db /data/goals.db && rm -f /data/goals.db-wal /data/goals.db-shm"
docker compose start
```

### Безопасность сервера

- Входите по SSH-ключу, а не по паролю: `ssh-keygen -t ed25519` на своём компьютере, затем `ssh-copy-id root@94.228.170.88`.
- После проверки входа по ключу запретите пароли: в `/etc/ssh/sshd_config` установите
  `PasswordAuthentication no` и `PermitRootLogin prohibit-password`, затем `systemctl restart ssh`.
- Если пароль root где-то публиковался или пересылался — смените его командой `passwd`.

`deploy/Caddyfile` содержит конфигурацию технического домена `94.228.170.88.sslip.io`. На сервере Caddy проксирует HTTPS на контейнер; порт `3001` наружу не открыт. Для собственного домена замените адрес в Caddyfile и перезагрузите Caddy.

## Публикация мини-приложения

1. Разместите API на HTTPS-сервере.
2. Соберите клиент с публичным адресом API:

```sh
VITE_API_URL=https://94.228.170.88.sslip.io npm run build
```

3. Укажите ID приложения в `vk-hosting-config.json` и выполните `npm run deploy`.

В production по умолчанию используется `https://94.228.170.88.sslip.io`, поэтому `npm run deploy` собирает клиент с рабочим API. Для другого сервера переопределите `VITE_API_URL` при сборке. Приложение использует `VKWebAppInit`, `VKWebAppGetUserInfo` и `VKWebAppShare`.
